## تحلیل

### گلوگاه اصلی: Event Loop Node.js

```
توان عملیاتی: ~1700-1800 req/s (ثابت از ۱۵۰۰ تا ۵۰۰۰ کاربر)
```

توان ثابته ولی تأخیر خطی بالا میره — یعنی SQLite همگام روی event loop اثر میذاره. وقتی N کاربر همزمان میرسن، تقاضاها در صف قرار میگیرن و تأخیر = N × زمان_یک_query است.

### سقف پیشنهادی

| سطح | تعداد کاربر همزمان | توضیح |
|---|---|---|
| 🟢 بهینه | ≤ ۴۰۰ | p99 < ۲۵۰ms — تجربه عالی |
| 🟡 قابل قبول | ≤ ۱۵۰۰ | p99 < ۱s — تجربه خوب |
| 🟠 کند ولی کارآمد | ≤ ۳۰۰۰ | p99 ~1.5s — تجربه قابل قبول |
| 🔴 آستانهٔ فروپاشی UX | ۵۰۰۰ | p99 > 2.5s — تجربه بد |

**نتیجه: فروشگاه تا ۱۵۰۰ کاربر همزمان بدون هیچ مشکلی کار می‌کنه. برای یک فروشگاه محلی این عدد بسیار بالاست.**

## ملاحظات

- بنچمارک روی **Sanbox ایزوله** اجرا شده — دیتابیس واقعی آسیب نمی‌بینه.
- سقف نرخ (rate-limit) در تست ۱۵۰۰-۵۰۰۰ باز بوده (raw performance).
- تست ۴۰۰ نفر با **سقفهای واقعی** (CGNAT view) اجرا شده.
- CPU Benchmark cụ thể هست — Real-world latency ممکنه ۱۰-۲۰٪ بهتر باشه (keep-alive, connection reuse).
